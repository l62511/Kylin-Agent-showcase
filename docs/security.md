# 安全与边界治理

## 输入与路径

- 请求体按声明长度和实际 ASGI 分块累计限制，超过上限在继续读取前返回 413。
- 文件路径先做规范化、白名单和保护路径判定；Docker 容器标识只接受限定字符集和 128 字符以内长度。
- 数据库表名先与已发现对象集合比对，再生成受控标识符，避免把用户输入直接拼进查询。

## 执行与幂等

- REST/A2A 共用 canonical JSON + SHA-256 指纹；相同 `client_request_id` 只允许一次副作用执行，指纹不一致返回冲突。
- SQLite WAL 记录 owner token、租约 TTL 与心跳；超时和进程异常不会留下永久占用。
- 取消、超时和容量拒绝都使用显式状态，避免调用方把“未知结果”误判为成功后再次执行写操作。

## 输出与敏感信息

- 命令、Docker socket 和数据库预览均采用固定上限的分块读取；上层收到 `truncated` 后必须按不完整结果处理。
- 容器 inspect、日志、环境变量、URL 和 JSON 字段统一脱敏，`PASSWORD/TOKEN/API_KEY/SECRET/Authorization/Cookie` 等字段不进入展示 DTO。
- SSE 普通事件允许合并或丢弃，终态、审批、错误和取消事件进入可靠缓冲，不因背压静默丢失。
